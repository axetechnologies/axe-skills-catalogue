01 · Behind the door

Ask for a name. A model answers.

Tools never carry a host, a port or a model id. They ask the door for a capability by name. Each name has an ordered list of servers; the first healthy one answers, and a full one is skipped rather than queued.

03 · AXe SURFACES

What stands around the door.

Each one is an AXe service Operator uses, run on AXe's own machines.

Identity · AuthGate

Sign-in and keys

Device-code sign-in (RFC 8628) for the terminal, OAuth for the web, one account across devices, and plans checked at the door. Fleet keys are issued through Keyhub; the master key stays on the server.

Artifacts · Temple

Where finished work lives

Every Operator surface publishes what it makes to Temple through one client. Pages render in a sandbox and share as a short link.

Skills marketplace

Skills, plugins and connectors

Operator searches this catalogue before public hubs. Everything in it arrives quarantined and stays there until it is reviewed; what you publish is held the same way. Counts and the live list are in section 04. Browse at skills.axe.onl or Barracks.

Knowledge · Skylark · beta

Search what the team wrote

Operator's knowledge_search reads Skylark, fed hourly in passage-sized pieces. Back in service on 24 November; alerting is not in place yet.

    05 · Checks

    It says what it did not verify.

    Every turn is written down with whether its result was checked.

    1. No unproven "done". An answer that reports passing tests that never ran gets one reminder, then a Not verified banner.
    2. Lessons kept at once. When a turn goes in circles, the lesson goes into memory right away and the step that broke the loop is saved as a training pair.
    3. A failing model is named. An error hidden inside a successful response counts as an error; another model answers the turn, and one line says why.
    4. Not yet: retraining. The records are kept. Training model weights from them is not switched on.

    If a claim cannot be inspected, it does not ship.
